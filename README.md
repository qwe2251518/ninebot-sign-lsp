# 九号出行自动签到 LSPosed 模块

打开九号出行 App 时自动签到；顺便可以把主页的电动车图片换成自己的图。

- **实测**：2026-10-15 真机运行，打开 App 即自动签到成功。
- **适配版本**：九号出行 **6.10.11**（Segway Mobility，versionCode 610114116）。
  版本更高时若闪退或签到异常，请降级回这一版。
- **安装包**：到 [Releases](https://github.com/qwe2251518/ninebot-sign-lsp/releases) 下载 `NinebotSign.apk`。
- **免责**：仅供学习交流，不破解任何付费内容，账号与设备风险自负。

## 使用说明

### 前提

- 手机已经 **root**（Magisk / KernelSU 等）
- 已装 **LSPosed**（Zygisk 版）并能正常打开
- 九号出行 App 是 **6.10.11** 这一版

### 安装

1. 安装 `NinebotSign.apk`。装完桌面会出现图标**「九号自动签到」**（不在桌面就在应用抽屉里），
   点开就是设置界面，签到开关、换图开关都在里面配，不用手动改配置文件。
2. 打开 **LSPosed → 模块**，找到「九号自动签到」，打开开关。
3. 点进模块，在 **作用域** 里勾选「九号出行」。
4. **强制停止**九号出行，再重新打开。约 6～10 秒后会弹 Toast 报告结果。

之后每次打开九号出行（含从后台切回来）都会自动检查一次；当天已经签过就不再打扰。

### 设置界面

桌面图标「九号自动签到」点开就是（v2.0），能配这几件事：

- **自动签到**：总开关；关掉之后模块就只剩换图这些功能
- **替换主页电动车图片**：勾上开关，再点「**从相册选择图片**」——图存进模块自己的私有目录，
  注入进程通过内容提供者取回来用：不需要任何存储权限，也不碰公共相册
- **动能回收（车控）**：四选一「关闭 / 弱 / 标准 / 不管」，默认「不管」＝模块完全不碰这一项。
  选前三个时，注入端会读车上 `rFunBool` 的当前值、只改低 2 位（关闭 0 / 弱 1 / 标准 2）再写回
  `setFunBool` —— 走的是九号自己的那条命令，不是另造一套协议。
  **不保证能用**：这是绕过九号界面直接改寄存器，可能发下去没反应，也可能被车机或服务端改回去。
  另外车不连蓝牙时命令发不出去（日志里搜「车控：动能回收」能看到发没发、失败在哪一步）。
- **项目主页**：界面底部有按钮，直接打开本项目的 GitHub 页

界面里**没有「保存」按钮**：开关一拨就存、单选框一选就存、路径框失焦就存。
换图和签到要**强制停止九号出行再打开**才生效；动能回收不用强停——注入进程每 1.5 秒复查一次配置。
配置存在模块自己那里，注入进程按两条通道读：内容提供者（主通道）+ `ninebot-sign.conf`（手改文件时用；
Android 11+ 上这个文件常常写不进去，那就以内容提供者为准）。

手改配置文件的老办法仍然保留：界面生成的配置带一行表头
`# 由「九号自动签到」设置界面生成；想手动改配置就先删掉这一行`，
只要这行还在，界面每次保存都会整份覆盖它；想纯手改就把这行删掉。

### 怎么看签到结果

- **Toast**：`九号签到成功，连续 N 天` / `今日已签到` / `签到失败：…`
- **日志**（出问题时看）：`/sdcard/Android/data/cn.ninebot.ninebot/files/ninebot-sign.log`，
  或在 LSPosed 日志里过滤 `NinebotSign`
- 签到成功的当天会写标记文件 `ninebot-sign.ok`。想当天再试一次，删掉它再重开 App。

### 换主页电动车图片（可选，默认关闭）

推荐直接在**设置界面**里勾「替换电动车图片」，再点「**从相册选择图片**」——选完开关会自动打开，
**强制停止九号出行再打开**就换好了。这条路径不需要任何权限：图先存进模块的私有目录，注入进程
通过内容提供者取回九号自己的私有目录，再喂给 Glide（文件名带「戳」，换了图不会拿到旧图）。

想手工放文件也行（模块会把它复制进九号的私有目录再用）：

1. 准备一张图片放在九号能读到的地方，比如 `/sdcard/Pictures/xxx.png`
2. 在设置界面的「**手工指定图片路径**」里填这个路径（或写进 `ninebot-sign.conf`：
   `vehicleImagePath=/sdcard/Pictures/xxx.png`）
3. **强制停止九号出行再打开**

> 注意：**老教程里的 `/sdcard/Android/data/cn.ninebot.ninebot/files/vehicle.png` 在 Android 11+
> 上用不了** —— 那个目录连九号出行自己写都会被系统拒绝（日志里是 `open failed: EACCES`），
> 所以别再往那儿放图，也别指望往那儿写 `ninebot-sign.conf`。

其它开关：

- 临时关掉 → 界面里关掉开关（老办法：九号私有目录里建个空文件 `vehicle-image-off`，需要 root）
- 彻底回滚 → 界面里关掉开关、清空路径

### 常见情况

| 现象 | 说明 |
| --- | --- |
| 弹「检测到该应用在hook环境中运行」 | 九号 App 自带的反 hook 提示，装了 Xposed 模块就会弹，**不影响签到**。不想看到可用 Shamiko / DenyList 隐藏 |
| 九号出行闪退、打不开 | App 版本太高，降级回 **6.10.11** |
| 一直没有 Toast | 检查模块开关、作用域是否勾了「九号出行」、是否强制停止后重开；再看 `ninebot-sign.log` 有没有新行 |
| 日志只有「今日已签到成功过」 | 正常：今天已经签过了，当天不再发请求 |
| 换图没生效 | 开关要打开、**强制停止 App 再打开**；再搜日志里「车辆图配置：开关=…」那行是不是「开」 |
| 相册选图后主页没变 | 换完必须强制停止 App 再打开；日志里搜「车辆图」，出现「从设置界面取到 N 字节」说明图已经到手 |
| 动能回收改了没反应 | 先确认车连着蓝牙（日志里「车控：没有已连接的车」就是没连）；连上后日志搜「车控：动能回收」，会打「读到的 rFunBool → 改后写回的值」；这一项本来就**不保证能用**，也可能被车机/服务端改回去 |

### 卸载 / 回滚

1. LSPosed → 模块 → 关掉「九号自动签到」，重启九号出行（或重启手机）
2. 像普通应用一样卸载「九号自动签到」
3. 清理残留：删掉 `/sdcard/Android/data/cn.ninebot.ninebot/files/` 下的 `ninebot-sign.ok`、
   `ninebot-sign.log`、`ninebot-sign.ql`、`vehicle.png`、`vehicle-*.png`、`vehicle-cache-*.png`、
   `ninebot-sign.conf`（这个目录 Android 11+ 上一般看不到，要用 MT管理器/root 或干脆不管它）

## 工作原理

- 九号的签到不在 APK 里，签到页是 H5 页面，所以没法去 hook「签到方法」。
- 模块的做法是在 App 进程内拿到登录凭据，自己向签到接口发请求，再把结果用 Toast 报出来。
- 触发时机：冷启动，以及每次有页面回到前台；当天成功过就只记一行日志，不再打扰。
  动手前先查一次签到状态，能确定今天已签就直接收工。
- 主页那张车图是 Glide 加载的远端图片，模块在同一个 hook 点把图源替换成本地图片。

## 从源码构建

```
.\build.ps1   # aapt2 compile(res/图标) -> aapt2 link -> 塞 classes.dex/assets -> zipalign -> apksigner
```

需要 JDK 与 Android SDK build-tools（`aapt2` / `zipalign` / `apksigner`）。产物是 `NinebotSign.apk`。

⚠️ Xposed 模块必须是**单个 `classes.dex`**：AGP 的 debug 构建会拆出 `classes2.dex`，那样 LSPosed
勾选了也不会注入；脚本里有一道硬校验。

## 源码结构

- `module/src/com/ninebotsign/lsp/SignHook.java` —— 注入逻辑与全部功能（单文件）
- `module/src/com/ninebotsign/lsp/SettingsActivity.java` —— 桌面上的设置界面（纯代码搭 UI，不依赖 androidx）
- `module/res/mipmap-*/ic_launcher.png` —— 设置界面的桌面图标
- `module/AndroidManifest.xml`、`module/assets/xposed_init` —— 模块声明与入口类
- `probe/` —— 离线自测：`HttpProbe.java`（请求与解析复跑）、`ModuleLogicTest.java`（直接编模块源码跑断言）、
  `RequestShapeTest.java`（本地回环抓真实请求，逐个头核对）、`SettingsTest.java`（设置界面 → 配置文件的文本往返），
  各带一份 `.txt` 报告。这些探针在 PC 上用 javac 直接编模块源码。
- `build.ps1` —— 手工出包脚本
